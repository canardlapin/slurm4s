## What the review got right, wrong, and missed

**Upheld as written.** The Slurm state model (1), remote failure flattening (2), `Scheduler.submit[A]`
type erasure (3), module boundary inversion (4), workflow functionality in core (8), the absent
property/law layer, the single-Scala-line build, and the honest-but-incomplete site qualification.

**Corrections.**

1. *The "delivered" flag is not misnamed.* `requestWriteCompleted` / `afterRequestWrite` /
   `writeCompleted` (`ssh/SshProcessRunner.scala:35,83`; `protocol/AgentProtocol.scala:148`) all say
   "write", and the write is genuinely local (`SshProcessRunner.scala:165`). No doc claims remote
   receipt. The real defect is narrower and worse: **only `TransportDisconnected` carries the flag**.
   `AgentUnavailable`, `AuthenticationFailed`, `RemoteCliFailure`, `RemoteAgentFailure`,
   `ProtocolViolation` and `ProtocolMismatch` have no such field (`AgentProtocol.scala:145-155`), so
   classifying into any of them silently destroys a `writeCompleted = true`. Rename nothing; fix the
   ADT.
2. *Missing-agent detection is a P0, not a P2.* `SshAgentWireClient.scala:128-150` accepts any
   nonzero exit whose stderr contains `not found`. An ssh exit 255 (connection dropped **after** the
   request frame was written) whose remote profile printed `module: command not found` classifies as
   `AgentUnavailable`, drops `writeCompleted`, and surfaces as
   `SubmissionAttempt.InvocationFailed` — a definite "never submitted" for a job that may be queued.
   That is exactly the false certainty the submit path's rescue branch exists to prevent.
3. *MiMa is not a misconfiguration.* `sbt-typelevel` derives previous artifacts from git tags;
   `git tag -l` is empty and nothing has been published, so `mimaPreviousArtifacts` is necessarily
   `Set()`. There is nothing to fix in the build — the fix is to cut a baseline (Phase F).
4. *`-Werror` is not merely "disabled", it was never enabled.* `build.sbt:15` sets only
   `-Xmax-inlines:64` and `-language:strictEquality`; `tlFatalWarnings` defaults to `false` in
   sbt-typelevel 0.8.7. Two plan documents assert `-Werror` is in CI. It is not.
5. *`ProtocolVersion` packing is fine.* Both components are non-negative `Int`, so the packed `Long`
   ordering is correct. Clarity improvement only; not release-blocking. Agrees with the review.
6. *`writeStable` already takes the sidecar lock.* Agrees with the review's own correction. The holes
   are `writeNew` (`AtomicFiles.scala:52`) and `claim` (`:133`), both unlocked exists-then-move.

**Missed by the review — and the most urgent item in this plan.**

`ClusterName` is not decorative; it is an active hang. `activeBound`
(`managed/ControlTransition.scala:735`) selects candidates via `requested.contains` using *stored*
refs, so candidates are found. But `byJob` (`:426`) keys on the *observation's* ref, which
`cli/SlurmParsers.scala:139` has just rewritten:

```scala
job = matched.copy(cluster = reportedCluster.orElse(matched.cluster)),
```

The lookup at `:428` compares a stored `cluster = None` against an observed `cluster = Some("alpha")`,
misses, and the observation is discarded with no diagnostic. `sbatch --parsable` yields no cluster on
a non-federated site (`SlurmParsers.scala:43-44`); squeue `v0.0.43` JSON does emit `"cluster"` (see
`fixtures/slurm-v0.0.43/squeue-pending.json:9`). So on an ordinary site, **every managed observation
is dropped and no attempt ever advances**. This is the same failure class as the `BOOT_FAIL` hang and
belongs at the front of Phase A.

**A third state classifier the review did not name.** Beyond `InterruptionClass.classify`
(`core/Observation.scala:33`) and `ObservationCoordinator.terminalState` (`managed:139`), there is
`FailureDiagnosis.stateCause` (`core/FailureDiagnosis.scala:447`). Three hand-written matches, all
omitting `BOOT_FAIL` and `DEADLINE`. The argument for one derived `Terminality` is stronger than the
review made it.

## Why this order

The review proposes P0 → P1 → P2 → P3 with laws at P2 and the module/kernel/batch work spread across
P1. Followed literally, that sequence **encodes the wire three times**: the state-model redesign
touches 52 `SlurmState` references in `protocol/AgentDomainJson.scala`, then P7.2 changes the byte
representation underneath those codecs, then P6f.12 hand-writes every codec again.

Three constraints actually bind:

- **Shape before representation before codec ownership.** EPIC P7 already established
  "representation (P7.2) before hand-writing codecs (P6f.12)". The correct generalization is that
  *public shape* must settle first too — and the `LaunchSpec` / `PreparedJob[A]` split is a larger
  shape change than P7.2 is a representation change.
- **The baseline must come last.** P7 established this for P7.2. Phase D makes it more important,
  not less: cutting 0.1.0 before the launch/result split would burn the MiMa baseline immediately.
- **Laws must precede the churn, not follow it.** The review places them at P2, after all
  architecture. That inverts their purpose. Phase D rewrites the submission path, the state model,
  and job identity simultaneously; property tests and `-Werror` are the net under that work, and are
  worth far less written afterwards.

The resolution is to split the P0 findings by whether they change public shape:

- **Semantics-only fixes** (Phase A) close every reachable hang and every false-certainty claim
  *without* touching public types, so none of the work is redone later.
- **Structural redesigns** (Phase D) — `ReportedState`, `JobRef` identity, `LaunchSpec`,
  `CallFailure`, the module cut — land together in one API-churn window, immediately before codec
  ownership.

Resulting sequence: **A + B (parallel) → C → D → E → F → G**.

## Phase A — Correctness hotfixes (P0, no public shape change)

Every item ships with a test that **fails against the pre-fix code**, per the P6f.28–P6f.39 standard.

- **A1. Cluster matching (the hang).** Normalize cluster out of the observation-matching key in
  `ControlTransition` and `SlurmCliScheduler.identity`; emit a diagnostic when a reported cluster
  differs from a stored one rather than silently dropping the row.
  *Test:* stored ref `cluster = None` + squeue JSON `"cluster": "alpha"` → observation applied.
- **A2. State model, additively.** Add `BOOT_FAIL`, `DEADLINE`, `SUSPENDED`, `RESIZING`, `REVOKED`,
  `SIGNALING`, `STAGE_OUT`, `STOPPED`. Stop discarding the flag suffix — `SlurmParsers.scala:502`
  currently does `takeWhile(c => c != '+' && !c.isWhitespace)`, so `CANCELLED+` loses the `+` with no
  record. Consume the full `job_state` array instead of `.headOption` (`:208-211`). Derive **one**
  `Terminality` and route all three classifiers through it.
  *Test:* a `BOOT_FAIL` accounting row is terminal and the awaiter exits instead of polling 24 h.
- **A3. Cancellation law.** `ssh/Slurm.scala:79` must inspect `afterRequestWrite` exactly as submit
  does at `:54`. Loss after writing the cancellation request yields `CancellationResult.Unknown` —
  which already exists (`core/FailureModel.scala:38`) and which the CLI backend already produces
  (`SlurmCliScheduler.scala:226`) — never a safely repeatable invocation failure.
  *Test:* mirror `RemoteSchedulerSuite.scala:9-24` for cancel; none exists today.
- **A4. Agent-unavailable classification.** Restrict to exit 126/127 plus narrowly enumerated
  diagnostics; drop the unbounded `contains("not found")` disjunct. Carry the write flag on every
  `AgentFailure` variant reachable post-write (see correction 1).
  *Test:* exit 255 with `module: command not found` in stderr and `writeCompleted = true` →
  acceptance-unknown, not "never submitted".
- **A5. Invariant closure.** `RelativeOutputPath` rejects `.` segments (`core/Workload.scala:10-21`
  rejects `..` but not `.`, so `a/./b` and `a/b` are distinct values that collide on write);
  `Fs2CommandExecutor.scala:80-86` and `SshProcessRunner.scala:130` contain all non-fatal exceptions
  rather than only `IOException`/`SecurityException`; `EventCursor.next` (`core/Identifiers.scala:72`)
  and `StoreRevision.next` (`managed/ManagedModel.scala:23`) return `Either` and guard overflow, as
  `AttemptEpoch.next` already does (`kernel/Identifiers.scala:85`); private constructors for
  `ResultContractDescriptor`, `DurableResultHandle`, `TaskInvocation` — the three outliers in a file
  where `ResultEnvelope` is already `private`; `ContentDigest` validates `sha256:<64 hex>` instead of
  accepting any ≤200-char text (`kernel/Identifiers.scala:73`).
- **A6. Native option ownership.** Add a renderer-owned denylist (`output`, `error`, `job-name`,
  `parsable`, `array`, `export`, and every typed key) rejected with a typed diagnostic, independent
  of `allowedNativeOptions`. Today `SlurmCommands.scala:111` appends native options after the typed
  ones and sbatch takes the last occurrence, so an allowed `output` silently breaks the log-path
  contract.

*Gate:* full suite green; each new test demonstrated red on the parent commit.

## Phase B — Assurance floor (parallel with A; gates D)

- **B1. `-Werror`.** Set `tlFatalWarnings := true` in CI and fix the fallout. Two plan documents
  already claim this is done.
- **B2. Properties and laws.** Add `discipline-munit` and `cats-laws` (neither is a dependency
  today). Generators for the identifier and evidence surface, then the first four law families in
  the review's order: attribution, submission/cancellation uncertainty, evidence monotonicity,
  result authority. Currently the repo has **zero** `forAll`, zero `Gen`, zero `checkAll` across 57
  test files, while `docs/plans/2026-07-23-site-layer.md:53-60` commits to both.
- **B3. Separate-JVM atomic tests.** Today's collision tests are same-JVM fibers on a local
  filesystem, and the claim race moves one source to *different* destinations — it never tests
  competing publishers targeting the *same* destination across processes.
- **B4. Cross-version lanes.** Add Scala 3.3.8 (LTS) and 3.8.4 test lanes. Publish from **3.3.8
  only** — because Scala 3 shares `_3` coordinates, a careless `+publish` across both lines would
  attempt the same artifact twice. Doing this now surfaces LTS compile errors while the API is still
  moving and they are cheap to fix.

## Phase C — Atomic publication (P0, isolated to kernel)

- **C1.** `writeNew` and `claim` take the same sidecar lock as `writeStable`/`publishOnce`; one
  coherent destination-collision protocol rather than three.
- **C2.** Force the containing directory after rename, or narrow the wording. `stageAndMove` forces
  file contents (`AtomicFiles.scala:213`) and never the parent, while the class doc (`:19`) says
  "stable storage".
- **C3.** Split the documented guarantee into three — atomic visibility, single-publisher/no-replace,
  crash durability — and qualify each per filesystem. Fail acquisition when a consumer needs a
  guarantee that cannot be established on the target filesystem. Defer `AtomicFsCapabilities` as a
  public ADT until per-consumer requirements are actually enumerated.

## Phase D — Architectural settlement (one API-churn window)

- **D1.** `Scheduler.submit(spec: LaunchSpec)` — type-erased, honest. `Scheduler.scala:12` currently
  accepts `JobRequest[A]` and returns `SubmissionAttempt`; `A` is phantom.
- **D2.** `PreparedJob[A]` = `LaunchSpec` + `ResultPlan[A]` + content digest;
  `PreparedAttempt[A]` = `PreparedJob[A]` + attempt identity + epoch. Adopt the reviewer's refinement:
  keep reusable prepared content separate from attempt-specific identity so a new attempt is not
  baked into a reusable workload definition.
- **D3.** `ReportedState` = base token + flags, with **no manufactured base state** when a CLI surface
  reports only a flag. `Terminality` derived, never hand-written. This is A2 made structural.
- **D4.** `JobRef` operational identity becomes single-cluster; reported cluster demoted to evidence;
  federation and cross-cluster routing declared unsupported for v1. This is A1 made structural.
- **D5.** `CallFailure` algebra preserving protocol / transport / remote-agent distinctions to the
  boundary. Absorbs P7.5, which covers only the agent↔client wire and not the scheduler adapter's
  flattening at `ssh/Slurm.scala:219`.
- **D6.** Module cut: protocol (wire DTOs, limits, codecs, client contract) / ssh-client / agent
  (server assembly) / task-remote / worker. `build.sbt:128-130` currently has the client `ssh`
  module depending on `agent` and `worker`, and `Slurm.scala:38` extends the server-side `AgentApi`.
  Split the kernel into a pure contract artifact and an effectful filesystem artifact — ADR 0001 says
  "Cats Effect and FS2 are confined to interpreter/application modules" while `AtomicFiles` exposes
  `Sync`. Remove the `SharedKernel` aliases.
- **D7.** Extract grids, axes, encoders, sharding, gang plans and topology from
  `core/Batch.scala` (602 lines, ~18% of core) into `slurm4s-batch`. Core retains identifiers,
  resources, launch spec, job identity, reported state, result models, and `Scheduler[F]`. Make
  `Grid.product` lazy with a `Long` size and an overflow guard — it currently materializes eagerly
  and reports `Int` (`Batch.scala:21-29`), so two 100k grids OOM with no typed failure.

*Gate:* one lowering representation, not a separate batch IR and task IR.

## Phase G — Ergonomics, scale, qualification

**G1** compact `Job` surface with named products and literal interpolators — dynamic values return
`Either`/`ValidatedNec`, literals check at compile time. This retires
`docs/examples/typed-task.md:15-18`, whose flagship example opens with four consecutive
`.from(...).toOption.get` calls. No large fluent builder DSL. **G2** shared await coordinator so
direct handles join batched observation — today `RemoteTask.scala:148` gives every handle its own
loop and `RemoteBatch.scala:93` runs `elements.parTraverse(_.awaitValue)`, so 4,096 direct handles
are 4,096 ssh processes per tick against the managed coordinator's 16 batched calls. **G3** batched
result reads. **G4** real-site campaign; **two sites** before any production-support claim.

## Open decisions

1. **Supersede vs. coexist.** This plan assumes one merged epic replacing P7's ordering.
   The alternative — a P0 lane in front of an otherwise untouched P7 — preserves P7's recorded
   rationale but does codec work twice. *Recommendation: supersede.*
2. **Release target.** This plan assumes 0.1.0 experimental at Phase F, 1.0 after G4.
   *Recommendation: as written* — an earlier baseline burns on Phase D.
3. **Wire compatibility for A2/A5.** No tags, nothing published, so tightening `ContentDigest` and
   reshaping state need no migration story. Confirm nothing is persisted in a user's store already.
4. **Federation.** D4 declares it unsupported for v1. Confirm no near-term site requires `-M`.
5. **Phase A branch policy.** A1–A4 are hotfixes to reachable hangs. Whether they ship as a
   `0.0.x`-style pre-baseline tag or wait for Phase F is a release-cadence call.

### What the plan got wrong

Worth recording, because the corrections were more useful than the plan's own predictions:

- **The journal break was avoidable.** D1 was expected to invalidate every stored `attemptId`.
  `encodeSubmitRequest` turned out to be already launch-shaped, so the field set stayed
  byte-identical and no fixture changed. The real fix was refusing a contract the protocol cannot
  carry rather than silently rewriting it.
- **`-Werror` paid for itself immediately.** Enabling it exposed two non-exhaustive `SlurmState`
  matches that A2 had introduced *under a green 328-test suite* — latent `MatchError`s on exactly
  the states A2 existed to handle. This is the strongest evidence for the plan's claim that Phase B
  belongs before Phase D.
- **Cluster identity was worse than "decorative".** The review called it a modelling wart; it was
  dropping every managed observation and accounting record on any ordinary site.
- **Two false-certainty paths were found that the review never named**: a remote *file*
  permission error classified as OpenSSH authentication failure (A4), and `ProtocolViolation` on a
  zero-exit ssh reported as a definite non-submission (D5).
