# Golden fixture provenance

Fixtures are evidence, not anonymous test strings. Every captured Slurm fixture directory must
contain the raw bounded stdout/stderr bytes, a `provenance.json` sidecar, and the expected
normalized result.

The sidecar records:

- fixture schema version and stable fixture ID;
- exact argv vector, executable identity when available, locale, and relevant environment keys;
- Slurm version, cluster name, data-parser/plugin version, and command exit code;
- capture timestamp and source (`synthetic`, `disposable-cluster`, or `real-site`);
- byte counts, truncation flags, and SHA-256 digests for each raw stream;
- redactions as explicit ranges and reasons, never silent edits;
- expected parser family and normalized semantic result;
- license/redistribution constraint when evidence came from a real site.

Synthetic fixtures must say which invariant or fault they exercise. Real evidence must remove
credentials, usernames, paths, account names, and workload content without erasing the structural
condition under test. Raw fixture changes receive review like parser code.

`modules/core/src/test/resources/fixtures/wire-envelope-v1.json` is the first byte-exact protocol
fixture. It is synthetic, contains no private data, and proves canonical key ordering and the
trailing-LF policy.

`modules/protocol/src/test/resources/fixtures/python-result-envelope-v1.json` is generated by the
standard-library Python reference producer. The Scala decoder re-encodes it byte-for-byte and
checks the language-neutral result bindings.

`modules/protocol/src/test/resources/fixtures/agent-methods-v1.json` is the language-neutral v1
registry of every request method name. The envelope test exercises every entry with non-ASCII JSON
content and fails if the Scala method set adds, removes, reorders, or renames a wire method without
an explicit compatibility update.

`modules/cli/src/test/resources/fixtures/slurm-v0.0.43/` is the first Slurm-shaped parser fixture.
Its provenance explicitly sets `supportClaim` to false: it verifies unknown-state preservation and
version routing before real-site evidence is available, but cannot establish Slurm compatibility
on its own.

`slurm-25.05-v0.0.43/` and `slurm-26.05-v0.0.43/` are version-scoped synthetic array fixtures.
They include stdout, stderr, expected normalization, byte counts, SHA-256 digests, exact argv, and
upstream lifecycle provenance. Both deliberately retain `supportClaim: false`. They prove that the
registered v0.0.43 codec handles the selected shapes consistently across labeled major families;
they do not prove that those bytes came from a running Slurm binary or that a site is supported.

`squeue-state-truncation-v1/` is a provenance-pinned synthetic pair of otherwise identical
`CANCELLED` observations. One state expression ends in `+`; the other is complete. It proves the
parser and public observation preserve that distinction without pretending to identify omitted
flags.

`slurm-25.05.6-v0.0.43-actual/` is an exact capture from an actual Slurm 25.05.6 binary in a
disposable single-node controller. The controller accepted a two-element serial array and emitted
one compressed pending record with `array_task_string: "0-1%1"`; the fixture proves real-binary
parser compatibility and bounded matching to the two requested elements. The disposable worker
did not register, so the record deliberately retains `siteSupportClaim: false` and
`supportClaim: false`: it is not execution, accounting, or real-site acceptance evidence.
